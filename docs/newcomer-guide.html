Týmový účet převezmete
na tištěné kartičce.

UPN a TAP vlevo, QR vpravo. Ukázkové údaje neplatí.

Organizátoři plánují předat každému týmu fyzickou kartičku ve formátu vizitky. Vlevo bude UPN (celé přihlašovací jméno týmu) a TAP (Temporary Access Pass); vpravo QR kód odkazující na https://aka.ms/rakathon2026.

  1. Převezměte kartičku svého týmu

    U organizátorů ověřte, že kartička patří vašemu týmu. Ukázkové údaje z tohoto průvodce nepoužívejte.

  2. Naskenujte QR kód a přihlaste se

    QR otevře pouze portál; nepřihlásí vás automaticky. Do přihlášení Microsoftu zadejte celé UPN z kartičky a použijte její TAP. QR neobsahuje UPN ani TAP.

  3. Kartičku chraňte

    Obsahuje přihlašovací údaje. Nefotografujte ji pro veřejné sdílení, nedávejte ji do Gitu ani veřejného chatu. Platnost TAP si ověřte u organizátorů; při ztrátě kartičky nebo nefunkčním TAP je kontaktujte.

TAP není API klíč. Týmový API klíč si zkopírujete až po přihlášení v sekci Váš API klíč. Soukromý soubor teamNN.md, pokud vám jej organizátoři poskytnou, může sloužit jako záložní předání údajů.

Použijte účet
přidělený vašemu týmu.

  • Převezměte tištěnou kartičku svého týmu
  • Přihlaste se celým uživatelským jménem a TAP
  • V portálu zkontrolujte přihlášeného uživatele

  1. Převezměte týmovou kartičku

    Od organizátorů získáte tištěnou kartičku s UPN a TAP. Ověřte si platnost TAP. Pokud dostanete i záložní soubor teamNN.md, uchovávejte ho stejně bezpečně jako kartičku; necommitujte ho ani nesdílejte mimo tým.

  2. Otevřete portál pro účastníky

    Naskenujte QR z kartičky nebo otevřete https://aka.ms/rakathon2026. Pokud jste u Microsoftu již přihlášeni jiným účtem, použijte samostatný profil prohlížeče nebo anonymní okno. Zadejte celé UPN z kartičky, nikoli běžný osobní či pracovní účet.

  3. Dokončete přihlášení k Microsoftu

    Při přihlášení použijte TAP a postupujte podle případných pokynů k nastavení ověřování. V portálu pro účastníky zkontrolujte přihlášeného uživatele.

Upozornění

TAP není API klíč pro modely. Funguje pouze v době platnosti potvrzené organizátory a může být jednorázový. Pokud vypršel, ještě neplatí, byl již použit nebo nelze přihlášení dokončit, požádejte organizátory o pomoc.

Ověřte připojení
jedním krátkým voláním.

bashcurl / Chat Completions
~ ❯ curl https://apim-[address].azure-api.net/openai/v1/chat/completions \
  -H "api-key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-6-1-sol-dz-eu",
    "messages": [{"role": "user", "content": "Ahoj"}]
  }'

V sekci Modely vyberte textový deployment. Například pro gpt-6.1-sol je nakonfigurován deployment gpt-6-1-sol-dz-eu; před použitím ověřte, že je v seznamu. Pokud vyberete jiný textový deployment, změňte v příkladu hodnotu model.

Na slidu je zkrácená ukázka: apim-[address].azure-api.net je zástupná adresa gateway, kterou nahraďte adresou z portálu. Barvy rozlišují adresu, cestu /chat/completions, proměnnou $API_KEY, název deploymentu a zprávu Ahoj. Prompt ~ ❯ není součást příkazu. Níže je úplný příklad se skrytým zadáním klíče.

Příklad spusťte v Bashi s nainstalovaným curl. Zadávání klíče je skryté a jeho konkrétní hodnota se neuloží do historie příkazů. Úspěšný požadavek vrátí JSON s odpovědí asistenta.

Do prostředí projektu nainstalujte balíček openai. SDK vyžaduje api_key; hodnota "unused" je placeholder, nikoli přihlašovací údaj. Skutečný klíč gateway patří do default_headers.

Python

from getpass import getpass
from openai import OpenAI

client = OpenAI(
    base_url="https://apim-rakathon-q7146n.azure-api.net/openai/v1/",
    api_key="unused",
    default_headers={"api-key": getpass("Týmový API klíč: ")},
)
reply = client.chat.completions.create(
    model="gpt-6-1-sol-dz-eu",
    messages=[{"role": "user", "content": "Ahoj"}],
)
print(reply.choices[0].message.content)

Konfigurace zahrnuje modely OpenAI, xAI, DeepSeek, Moonshot AI / Kimi a Microsoft AI. Generování obrázků používá /images/generations, nikoli /chat/completions; ne každý model podporuje všechna API a parametry. GitHub Copilot

GitHub Copilot je
AI parťák pro vývoj.

  • Vysvětlí kód a navrhne řešení
  • Doplňuje kód, pomáhá s testy a opravami
  • Agent může upravit soubory a spustit nástroje

GitHub Copilot je AI asistent pro vývoj softwaru: nabízí doplňování kódu, chat nad projektem a agentní práci na zadaném úkolu. Pokud znáte Claude Code, Cursor nebo Codex, princip je podobný: popíšete cíl a dáte nástroji kontext projektu. Copilot je propojený s GitHubem i běžnými vývojářskými nástroji; není to jen jeden model nebo pouze našeptávání kódu.

Agent podle dostupných oprávnění může projít repozitář, navrhnout postup, měnit soubory a spouštět testy. Na GitHubu může cloud agent připravit změny v pull requestu. Výsledek vždy zkontrolujte a ověřte; do promptů nevkládejte TAP, API klíče ani data, jejichž použití není pro vaši výzvu povolené.

První úkol: „Vysvětli strukturu tohoto projektu a navrhni nejmenší změnu, která přidá formulář. Nejdřív mi ukaž plán.“ Funkce a dostupné modely závisejí na klientovi, licenci a nastavení organizace.

Začněte: oficiální quickstart pro GitHub.com ukazuje otázky nad souborem i zadání úkolu cloud agentovi. Co je GitHub Copilot. Ověřeno 15. října 2026.

Vyberte si prostředí,
ve kterém už pracujete.

  • IDE: doplňování, chat a úpravy projektu
  • Terminál: GitHub Copilot CLI
  • GitHub.com nebo Copilot app: otázky a agentní úkoly

  • V IDE: například VS Code, Visual Studio nebo JetBrains. Doplňování při psaní, chat nad kódem a agentní úpravy projektu podle podpory daného editoru.
  • V terminálu: GitHub Copilot CLI. Pracuje v adresáři projektu; po instalaci spusťte copilot a při prvním použití se přihlaste přes /login.
  • Na GitHub.com: bez instalace otevřete soubor v repozitáři, klikněte na ikonu Copilotu a ptejte se na kód. Pro začátek zkuste „Vysvětli tento soubor“ nebo „Jaké testy této funkci chybí?“. Dostupný cloud agent může zpracovat zadaný úkol a připravit pull request.
  • V GitHub Copilot app: samostatné prostředí pro práci na projektech a koordinaci agentních úkolů, repozitářů a pull requestů.

Ve všech prostředích používejte stejný osobní GitHub účet, kterému byla přidělena hackathonová licence. Copilot nepoužívá týmový TAP ani api-key Azure gateway. Licence pro Copilot neaktivuje předplatné Cursoru, Claude Code ani jiného samostatného nástroje.

Přístup získáte
svým GitHub účtem.

Portál pro účastníky → GitHub Copilot → registrace. Nejde o týmový Azure účet.

Pro účastníky je připraven GitHub Copilot s placenou licencí a kreditem pro akci. Registrace je oddělená od přihlášení do Azure. Otevřete sekci GitHub Copilot v portálu pro účastníky a zvolte Registrovat se pro GitHub Copilot, nebo naskenujte registrační QR níže.

  1. Ověřte akci a přihlaste svůj GitHub účet

    Na registrační stránce musí být Rakathon 2026. Zvolte Sign in with GitHub a použijte osobní účet GitHub.com, se kterým budete během akce pracovat. Pokud účet nemáte, použijte Create a GitHub account. Enterprise Managed User (EMU) účty nejsou podporované. Nevkládejte sem týmové Azure UPN, TAP ani API klíč.

  2. Přečtěte si podmínky a požádejte o pozvánku

    Přečtěte si Participation Agreement včetně dopadu na licenci Copilotu. Pokud s podmínkami souhlasíte, potvrďte je a zvolte Request organization invitation.

  3. Přijměte pozvánku a ověřte licenci

    Dokončete přijetí pozvánky podle registrační stránky. Stav přístupu ověřte v nastavení Copilotu a stejným GitHub účtem se přihlaste v IDE, CLI nebo app. Pokud odkaz vypršel, pozvánka nepřijde nebo Copilot není aktivní, kontaktujte organizátory.

Licence a dočasná organizace

Podmínky registrace upozorňují na zrušení stávajícího individuálního předplatného Copilotu při připojení; zvažte samostatný GitHub účet pro akci. U firemní licence postupujte podle pokynů k Usage billed to na registrační stránce. Organizace akce i její obsah mají být podle SWA odstraněny 19. října 2026: práci, kterou chcete zachovat, si včas uložte mimo ni. Nesdílejte citlivá data ani klíče.

Od nápadu k prototypu v Azure

Jednoduchému webu stačí
Static Web Apps.

  • Rozcestník, vizualizace CSV nebo dashboard
  • Začněte plánem Free a statickým frontendem
  • API klíče do prohlížeče nepatří

Vyberte nejmenší sestavu, která předvede váš nápad. Jde o inspiraci pro MVP / PoC, ne o produkční architektury ani předem nasazené služby. Vše vytvářejte ve vlastní rg-teamNN; dostupnost služby, region, kvóty a cenu ověřte před nasazením.

Nápad: rozcestník týmu, vizualizace CSV nebo dashboard nad povolenými anonymizovanými daty. HTML/CSS/JavaScript, React nebo Vue sestavte jako statické soubory a publikujte přes GitHub Actions. Čistě statický web backend nepotřebuje.

  1. Prohlížeč
  2. Static Web Apps
  3. Statické soubory

Tier: začněte plánem Free; má omezené kvóty a nemá SLA. Standard je placený, pro běžnou statickou ukázku není nutný. API klíč modelů ani databázové přihlašovací údaje do frontendu nepatří.

Začněte: Microsoft Learn: první Static Web App obsahuje i odkazy na startovací GitHub šablony. Porovnání Free a Standard.

Platnost doporučení

Podmínky plánů a nabídek v této kapitole byly ověřeny 15. října 2026 v odkazované dokumentaci Microsoftu. Nejde o cenovou nabídku ani potvrzení zbývající free kapacity v subscription akce. Consumption znamená platbu za použití, nikoli automaticky zdarma.

Formulář ukládá data
přes vlastní API.

  • Static Web Apps, Functions, Azure SQL Database
  • SQL free offer nejprve potvrďte s organizátory
  • Serverless databáze neznamená automaticky zdarma

Nápad: evidence požadavků, registrace nápadů nebo hodnocení návrhů. Frontend zobrazuje formulář a seznam; vlastní HTTP API kontroluje vstupy a čte či zapisuje data.

  1. Static Web Apps
  2. HTTP Function
  3. Azure SQL Database

Tier: SWA Free, samostatná Function App v Flex Consumption / On Demand, SQL Database free offer, pokud je dostupná. Nejde o MySQL ani o virtuální server se SQL Serverem. Pro připojení samostatného API k frontendu platí pravidla CORS a autentizace z následujícího scénáře.

SQL free offer je omezená na 10 databází v celé subscription, ne na každý tým; dostupný počet a společný region nejprve potvrďte s organizátory. Při vytvoření musí být vidět Free offer applied! a zvolte Auto-pause the database until next month. Nepřepínejte na automatické placené pokračování. Pokud nabídka není dostupná, placenou variantu nejprve schvalte; samotné označení serverless neznamená zdarma. Po pauze může první požadavek trvat déle.

Přihlašovací údaje databáze patří jen do serverové konfigurace. API musí mít povolené síťové připojení k SQL; nepovolujte kvůli demu všechny IP adresy. Bez potřeby relačních dotazů zvažte jednodušší Azure Table Storage, účtované podle uložených dat a operací.

Začněte: Microsoft Learn: HTTP Function a zápis do SQL, vytvoření SQL free offer a její limity. Návod používá SQL binding v samostatné Function App, ne v omezeném managed API SWA; nastavení sítě přizpůsobte pravidlům akce.

  2. HTTP Function
  3. Týmová AI gateway

Tier: samostatná Function App v Flex Consumption / On Demand, bez Always ready. Výpočet se účtuje podle běhu a počtu spuštění, s free grantem pro způsobilé subscription. Storage a monitoring se účtují zvlášť; čekání na odpověď modelu také prodlužuje běh. Po nečinnosti počítejte s cold startem.

Pro krátké HTTP API může stačit také managed Functions API přímo ve SWA Free: nasazuje se s webem do /api. Nepodporuje ale Durable Functions, ne-HTTP triggery ani managed identity. Samostatné API volejte přes jeho HTTPS URL; povolte CORS jen pro vlastní frontend a ověřujte uživatele. Přímé propojení vlastní Function App pod /api ve SWA vyžaduje Standard, není nutné kvůli němu automaticky upgradovat. CORS samo o sobě není autentizace.

Chraňte API před veřejným zneužitím a omezte délku vstupu i počet volání. Týmový klíč nepatří do JavaScriptu prohlížeče; vlastní Foundry resource není potřeba.

Levný prototyp začíná
kontrolou nasazení.

  • Free limity sdílí subscription, ne každý tým
  • Vše nasazujte do své rg-teamNN
  • Po demu ukliďte vlastní prostředky, ne celou skupinu

  1. Vyberte nejmenší scénář

    Ověřte plán, region, odhad ceny, související prostředky a kvóty; free granty Functions a Container Apps jsou sdílené v subscription, nikoli přidělené každé rg-teamNN.

  2. Přizpůsobte návod týmovému prostředí

    Novou resource group nahraďte svou existující rg-teamNN. Contributor ve skupině nemůže přidělovat RBAC role ani registrovat resource providery na subscription; pokud je vyžadují automatické šablony nebo managed identity, požádejte organizátory. Nezakládejte vlastní subscription a nespouštějte cizí deploy šablony naslepo.

  3. Použijte připravenou AI gateway

    Nevytvářejte kopii sdíleného Foundry či APIM. U AI ukázek přizpůsobte backend týmové gateway podle prvního API příkladu. Používejte jen data povolená pro vaši výzvu; API a web s neveřejnými daty nesmí zůstat anonymně přístupné.

  4. Omezte škálování a kontrolujte náklady

    Nastavte rozumné škálování, omezené retries a úsporné logování bez tajných údajů. Cost Management sledujte, pokud k němu máte přístup; jinak náklady potvrzují organizátoři. Rozpočet modelového API nekryje libovolné Azure služby a alert sám infrastrukturu nevypne.

  5. Ukliďte jen své nepotřebné prostředky

    Po demu po dohodě odstraňte vlastní nepotřebné prostředky včetně placených závislostí. Pouhé zastavení aplikace nemusí zastavit účet za registry, databázi, disky nebo logy. Nemažte celou týmovou resource group podle závěrečného cleanup příkazu v cizím tutoriálu.

Záměrně vynecháváme produkční sizing, vysokou dostupnost a složité síťové topologie. Pokud je ale kvůli datům vyžaduje zadání nebo Azure policy, neobcházejte je kvůli levnějšímu demu.

Limity a pomoc

Krátká volání
šetří týmový rozpočet.

  • Začněte krátkými prompty a málo souběžnými požadavky
  • Při rate limitu vyčkejte; zastavte opakování ve smyčce
  • Rozpočty potvrzují a přístup obnovují organizátoři

Používání modelů má týmový rozpočet. Před jeho vyčerpáním dostávají organizátoři upozornění; po dosažení týmového limitu se přístup pozastaví. Sdílený limit celé akce může zastavit všechny týmy dříve. Výchozí kvóta je 4 miliony tokenů na tým a den, společná pro textové modely.

Jde o výchozí nastavení, nikoli aktuální zůstatek. Skutečný příděl a spotřebu potvrzují organizátoři. Začněte krátkými prompty a malým počtem souběžných požadavků. Při chybách zastavte opakované pokusy ve smyčce; po překročení rate limitu vyčkejte a respektujte Retry-After, pokud je uveden. Pozastavený přístup mohou obnovit pouze organizátoři.

Sdílejte chybu.
Nikdy tajné údaje.

  • Tým, endpoint, deployment, status a čas
  • 401: klíč či pozastavený přístup; 429: limity
  • Skryjte citlivé údaje; neposílejte TAP ani API klíč

  • Přihlášení nefunguje: zkontrolujte celé týmové jméno, platnost a jednorázovost TAP a zda prohlížeč nevybral jiný účet.
  • Účet není týmový: odhlaste se a použijte přidělený účet teamNN.
  • Klíč se nenačítá: zkuste načtení či přihlášení znovu; informujte organizátory nebo použijte záložní API údaje z předávacího souboru, pokud jej máte. TAP není API klíč.
  • HTTP 401: zkontrolujte hlavičku api-key, zkopírovaný klíč, URL gateway a aktivní stav týmu. Pozastavení také vrací 401.
  • Suspended / zablokováno - rozpočet: kontaktujte organizátory. Nový klíč pozastavený přístup neobnoví.
  • HTTP 404 nebo nepodporované parametry: ověřte přesný název deploymentu a API vhodné pro daný model.
  • HTTP 429: rate limit, sdílená kapacita nebo kvóta tokenů; vyčkejte místo opakování ve smyčce.
  • Zamítnutý přístup ke storage: organizátoři zkontrolují účet a adresář, role Reader a Blob Data Reader a povolenou síť.
  • Katalog nefunguje nebo je zastaralý: požádejte organizátory o kontrolu exportu katalogu a nasazení portálu.

Přiložte název týmu, prováděnou akci nebo cestu endpointu, název deploymentu, HTTP status, čas a chybovou zprávu bez citlivých údajů. Nikdy neposílejte TAP ani API klíč.

Můžete začít: správný týmový účet, aktivní klíč gateway a jedno úspěšné volání modelu.
